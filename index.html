03 / how I work

Less ceremony. More signal.

~/imz/process.sh ● live
  1. 01

    Listen, then ask the harder question

    The brief is rarely the problem. I find the actual constraint — usually buried in data flow or a stakeholder dependency — before opening an editor.

  2. 02

    Schema first. Always.

    Database design dictates everything downstream. Get the schema right and the API writes itself. Get it wrong and you'll be paying interest forever.

  3. 03

    Ship vertical, not horizontal

    One full feature path — DB → API → UI → tests → deploy — beats six half-built layers. Production feedback loops only happen on shipped code.

  4. 04

    Hand off cleanly

    Documented schemas, structured commits, reusable components, and a maintainer who isn't dependent on me to keep the lights on.
